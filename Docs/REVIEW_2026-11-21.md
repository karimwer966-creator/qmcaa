## 3. عوائق حاسمة (P0) — تمنع البناء أو التشغيل الآمن

### P0-1 — الـ include مفقود: السكربت لا يتجمّع
`Scripts/QSMC_Phase1_Test.mq5:2`
```mql5
#include <QSMC/QSMC_Root.mqh>
```
لا يوجد ملف بهذا المسار. الملف الفعلي هو `Include/QSMC/Core/QSMC_Root.mqh`.
تم التحقق آلياً من كل الـ includes: **حالة واحدة مفقودة فقط، وهي هذه**.
**الأثر:** خطأ تجميع فوري (`cannot open include file`).
**الإصلاح:** إنشاء ملف تجميعي `Include/QSMC/QSMC.mqh` (و/أو `Include/QSMC/QSMC_Root.mqh`) يعيد التصدير، ويكون هو نقطة الدخول الوحيدة لكل الوحدات. هذا يحلّ أيضاً مشكلة الاعتماد على المسارات الداخلية.

### P0-2 — لا يوجد خبير
`Experts/QSMC/QSMC.mq5` فارغ (0 بايت). لا `OnInit`, لا `OnTick`, لا `OnTimer`, لا `OnDeinit`, لا `OnTradeTransaction`.
**الأثر:** لا يوجد منتج قابل للتحميل على الشارت. طبقة `App/` (Bootstrap، Lifecycle، Orchestrator، EventDispatcher) فارغة أيضاً، أي لا يوجد مكان لدورة الحياة أصلاً.

### P0-3 — وضع التداول الحقيقي معلن بلا أمان
`Include/QSMC/Core/QSMC_Types.mqh:9` يعرّف `QSMC_MODE_REAL`، و`QSMC_MODE_REAL` قابل للاختيار من مدخلات الخبير المستقبلي مباشرة، بينما:
- `Execution/*` كلها فارغة (بما فيها `ExecutionPreflight`, `RiskManager`, `OrderManager`)؛
- `Safety/*` كلها فارغة (بما فيها `SafetyController`, `IncidentSafety`)؛
- `Docs/EXECUTION_SAFETY.md` فارغ.

لا يوجد أي شرط يمنع إرسال أمر حقيقي: لا فحص `ACCOUNT_TRADE_ALLOWED`، ولا `TERMINAL_TRADE_ALLOWED`، ولا `SYMBOL_TRADE_MODE`، ولا تأكيد صريح من المستخدم.
**التوصية العاجلة:** إمّا حذف `QSMC_MODE_REAL` من الـ enum مؤقتاً، أو حجبه خلف `#define QSMC_ENABLE_REAL 0` حتى تُنجَز `Safety + Preflight + Risk` وتوثيقها.

### P0-4 — الـ Magic لا يميّز النسخ المختلفة (تصادم مؤكد منطقياً)
`Include/QSMC/Core/QSMC_InstanceIdentity.mqh:31-35`
```mql5
ulong h = QSMC_HashString(symbol);
h = QSMC_HashString(IntegerToString((long)period), h);
h = QSMC_HashString(IntegerToString(m_account), h);
m_magic = QSMC_MAGIC_BASE + (h % QSMC_MAGIC_RANGE) + magic_offset;
```
الـ Magic مبني على (الرمز + الفريم + الحساب) فقط، **ولا يدخل فيه الـ Preset ولا بصمة المدخلات** — مع أن `CQSMCInputFingerprint` يُحسب في `QSMC_Root::Init` ولا يُستعمل في أي شيء يتعلق بالهوية.
**الأثر:** خبيران على نفس الرمز/الفريم/الحساب بإعدادات مختلفة يحصلان على نفس الـ Magic، فيدير كل منهما صفقات الآخر (وسيصبح هذا خطأً فعلياً بمجرد تنفيذ `OrderManager`).
كما أن `magic_offset` غير مُتحقَّق منه (يمكن أن يكون سالباً أو أكبر من `QSMC_MAGIC_RANGE`)، ما يُنتج Magic خارج النطاق المعلن أو تصادمات مع الحساب الأساسي.
**الإصلاح:** `magic = BASE + (hash(symbol|period|account|fingerprint) % RANGE)`، مع `magic_offset` مُقيَّد في `[0, RANGE)`، وحفظ الـ Magic في GlobalVariable للتحقق من إعادة التشغيل.

### P0-5 — آلة الحالات ديكور
في `QSMC_Types.mqh:30-39` ثماني حالات معلنة، لكن `QSMC_Root.mqh`:
- `Init` (سطر 23) لا يفحص الحالة الحالية: يمكن إعادة التهيئة أثناء `RUNNING` بلا أي اعتراض؛
- `Shutdown` (سطر 45) يقفز إلى `STOPPED` من أي حالة، حتى من `CREATED`؛
- `QSMC_STATE_RUNNING`، `SAFE_MODE`، `STOPPING` **لا تُستخدم إطلاقاً** في أي ملف؛
- `QSMC_ERR_INVALID_STATE` (الأنواع سطر 61) معرّف وغير مستخدم.

**الأثر:** لا يوجد ضمان "لا تنفيذ إلا في حالة RUNNING"، وهو شرط أساسي لأي منطق أمان لاحق.
**الإصلاح:** جدول انتقالات صريح (allowed/denied) داخل `Lifecycle` + دالة `Transition(to)` تُرجع `QSMC_ERR_INVALID_STATE`، ومنع أي أمر خارج `RUNNING`.

### P0-6 — لا حلقة زمنية ولا مراقبة صحة
`timer_ms` يُخزَّن ويُتحقق من حده الأدنى (`QSMC_Config.mqh:50`) لكنه **لا يُستخدم**: لا `EventSetTimer` ولا `OnTimer`، و`Infrastructure/QSMC_Clock.mqh` و`HealthMonitor.mqh` فارغان. لا توجد أي آلية لاكتشاف توقف البيانات أو انقطاع الاتصال.

## 5. ملاحظات معمارية (P2)

1. **لا عقود بين الوحدات.** `Docs/MODULE_CONTRACTS.md` و`DEPENDENCY_GRAPH.md` فارغان، فلا يوجد مصدر حقيقة لاتجاه الاعتماديات. الاتجاه المقترح الصريح:
   `Core ← Infrastructure ← Data ← Analysis ← Decision ← Execution/Presentation`، مع `Safety` كطبقة مستعرضة (تُقرأ ولا تعتمد على Decision).
2. **القدرة الخطرة قبل الضابط.** الترتيب الصحيح للبناء: `Safety + Preflight + Risk` **قبل** `Execution`، وليس بعدهما. حالياً العكس: الـ enums جاهزة والضوابط فارغة.
3. **لا مواصفة استمرارية.** مفاتيح GlobalVariable مشتقة من الـ Magic (`QSMC_InstanceIdentity.mqh:47-48`) لكن `StateStore` فارغ: لا خطة لاستعادة الصفقات المفتوحة بعد إعادة تشغيل المنصة، وهي أخطر حالة في أي EA.
4. **لا استراتيجية اختبار.** `Tests/Harness/QSMC_Selftest.mqh` فارغ؛ لا اختبارات وحدة، لا مصفوفة باكتست، لا "اختبار دخان" في CI. لا يوجد `README` ولا `.gitignore` ولا رخصة ولا CHANGELOG (فارغ رغم أن الإصدار 0.1.0).
5. **الأنواع بلا تعريفات بيانات.** `Data/` و`Analysis/` فارغان تماماً، أي لا يوجد `MarketSnapshot`/`Zone`/`Signal` structs؛ طبقة القرار ستُبنى على لا شيء.
6. **ثنائية الوقت/المنطقة الزمنية.** لا `Clock` منفّذ: أي دمج لاحق بين `TimeLocal`, `TimeCurrent`, `TimeGMT` سيخلق أخطاء موسمية صعبة التتبع.

## 7. مقتطفات إصلاح جاهزة (لم تُطبَّق بعد)

**أ. ملف تصدير موحّد** `Include/QSMC/QSMC.mqh`:
```mql5
#ifndef QSMC_MAIN_MQH
#define QSMC_MAIN_MQH
#include "Core/QSMC_Root.mqh"
// تُضاف بقية الوحدات هنا مع تقدّم المراحل
#endif
```

**ب. حراسة إعادة التهيئة** في `QSMC_Root::Init`:
```mql5
if(m_state == QSMC_STATE_RUNNING || m_state == QSMC_STATE_INITIALIZING)
{
   res.Set(QSMC_ERR_INVALID_STATE, "init rejected: already active");
   return false;
}
```

**ج. Magic يشمل البصمة** في `QSMC_InstanceIdentity::Build`:
```mql5
h = QSMC_HashString(m_fingerprint.Hex(), h);          // بصمة الإعدادات
m_magic = QSMC_MAGIC_BASE + (h % (ulong)QSMC_MAGIC_RANGE);
```
(مع تمرير البصمة أو قيمتها العددية إلى `Build`، وتقييد `magic_offset` في `[0, QSMC_MAGIC_RANGE)`.)

**د. سقف مخاطر صارم** في `SQSMCConfig::Validate`:
```mql5
if(risk_percent <= 0.0 || risk_percent > 2.0)  { err = "risk_percent must be in (0,2]"; return false; }
```
